# v1.9.0: native Codex coordination

Codex and Claude Code can share presence, file claims, resource claims, messages
and commit review on one machine. This release adds native Codex lifecycle hooks
so trusted local tool calls can stop before overwriting a live peer's file and
deliver unread peer messages between tool calls.

## What changed

- Setup installs Codex hooks with backups and preserves existing handlers.
  Doctor distinguishes configuration from runtime trust and delivery.
- Native sessions keep their identity across MCP reconnects. Shared transports
  carry session context per request; unused MCP connections do not create agents.
- Patch paths, including rename endpoints, are claimed together. A denied shell
  operation leaves no partial file or resource claims. Explicit work directories
  and directory aliases resolve to the correct workspace, including new files.
- Workspace and branch changes refresh presence during the heartbeat interval.
  MCP-only presence stays alive without silently renewing file edit warmth.
- Commit guards prefer the current session over a foreign repository marker.
  Push review uses the latest recorded attribution deterministically.
- Repeated setup preserves the original global git-hook rollback setting.
  SQLite is checked before setup changes configuration.
- Updated transitive dependencies within compatible ranges to resolve the
  advisories reported by the release-time npm audit.

## Install or upgrade

Requires git and Node 22.13+ on the 22.x line, or Node 24+. This is an MIT-licensed
source release, not an npm package or a bundled Node runtime.

Extract the source archive, or clone/update the repository, then run:

```sh
node setup.mjs
node cli/doctor.mjs
```

Windows users can instead run `./setup.ps1`. Restart agent sessions after setup.
In Codex, review and trust the new or changed hook definitions through `/hooks`.
Until then, use MCP check-ins, file claims and message polling. Keep the existing
coordination store when upgrading; no destructive schema migration is required.

## Validation and limits

The automated suite covers native event fixtures, real stdio MCP requests,
reconnects, heartbeat timing, isolated git repositories, concurrent claims and
installer idempotency. Release CI gates Windows, macOS and Linux on Node 22.13.0
and 24. The GitHub release body records the exact tested commit and results.

On the development machine, Codex CLI 0.153.3 reports hooks as stable and enabled.
This verifies feature availability, not trust or host delivery. A real two-session
Codex test through the trusted host dispatcher remains outstanding. Follow the
[native smoke check](../CODEX.md) before treating that integration as live-tested.

Protection is whole-file, on a single-user machine. Hosted tools and arbitrary
scripts are not guaranteed to trigger pre-write checks. Shell recognition is
heuristic. Git hooks can be bypassed by git options or alternate configuration;
this is coordination, not a security boundary. Read [security limits](../../SECURITY.md).

Uploaded ZIP and tar.gz assets come from the tagged commit. Verify them against
`SHA256SUMS`. Dependencies are installed from the included lockfile. See the
[release procedure](../RELEASING.md) for reproducibility and rollback details.
