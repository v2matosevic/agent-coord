# v1.9.1: closed-session cleanup and reliable coordination

Closed agents should stop blocking their peers. This release detects exited
native Claude/Codex client processes, prevents MCP background keepalives from
reviving ended sessions, and preserves an ended heartbeat that AD/Hephaestus
can read even when its fleet snapshot is older than the exit.

## Included changes

- Known owner-process exits invalidate presence on the next coordination check;
  updated MCP servers also check every five seconds. Fleet output excludes
  inactive agents' file/resource claims and queue entries.
- Real resume can replace or clear the old process owner. Closing one shared
  MCP transport does not terminate a still-live session.
- New sessions skip historical broadcasts from inactive senders. Direct mail,
  current-session broadcasts and searchable message history remain available.
- Stable overflow identities prevent name-pool exhaustion from impersonating a
  different session. Codex denial delivery works across the PowerShell boundary.
- File contention history records wait episodes and supplies budgeted waiter
  notices without unlocking or transferring another agent's claim.
- Includes native Codex hook support from the earlier v1.9.0 draft. See the
  [changelog](../../CHANGELOG.md) for the complete inherited changes.

## Install or upgrade

This is an MIT-licensed source release, not an npm package. Requires git and
Node 22.16+ on the 22.x line, or Node 24+. Download and extract a release archive,
or update your existing clone with `git pull --ff-only`, then run:

```sh
node setup.mjs
node cli/doctor.mjs
```

Open new agent sessions afterward. Existing MCP processes keep their loaded
code; `whoami` reports the running version, which should be `1.9.1`. Review new
or changed Codex hook definitions in `/hooks` if requested. The installer does
not alter hook trust. Keep the coordination store: the migration is additive.

## Verification and limits

The Windows source check passed all 52 isolated test suites and all 10 doctor
configuration checks. Tests include abrupt native client termination through
the real process-ancestry resolver and stdio MCP transport, a connected MCP
server across SessionEnd, live-owner protection, resume and stale snapshots.
The GitHub release body records the exact release commit, fresh dependency
audit, archive verification and release CI results.

Unknown owners, unrecognized launchers and permission failures retain the
original three-minute heartbeat fallback. If every coordination process is
killed, cleanup waits for the next reader or that timeout. UI updates follow
the consumer's polling interval. PID reuse is not birth-time verified and can
delay detection. Production cleanup never kills processes.

AD's existing heartbeat-reader contract was inspected and exercised with
marker fixtures; this release does not rebuild AD or claim native UI acceptance.
Configuration checks and event fixtures do not establish Codex hook trust or
live multi-session host delivery. No new native UI acceptance on macOS/Linux
is claimed. See [security limits](../../SECURITY.md).

Uploaded ZIP and tar.gz assets contain the tagged source and a top-level
`agent-coord-1.9.1/` directory. Check their SHA-256 hashes against `SHA256SUMS`.
Dependencies are installed from the lockfile rather than bundled. The
[release procedure](../RELEASING.md) covers verification and rollback.
